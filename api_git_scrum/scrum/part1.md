# Agile methods and Scrum: part 1

1.  The waterfall when building software often goes wrong due to lack of feedback and changed requirements that are not discovered until it is too late to adapt to them.
    
2.  Working with the customer: getting frequent feedback and suggestions, adapting to the customer's needs. People and talking together: daily stand-up meetings, collaboration with customers, stake holders and product owners as well as within the development team. 
    
3.  a) Decides the order of the Product Backlog: Product Owner  
    b) Decides how to build a feature: Developers  
    c) Helps the team when a test server has been down for two days: Scrum master, to contact the persons responsible for the blocker (the test server being down), or Developers if the developers are responsible for the test server  
    d) Talks to customers about what they need: Product Owner  
    e) Coaches the team when the Daily Scrum takes 45 minutes: Scrum master
    
4.  A new feature in the middle of a spring will be placed in the backlog. It should not be added to the backlog. In the next sprint planning, the new feature may be added.
    
5.  Sprint review is for presenting the newly developed features and getting feedback. The participants are the developers, stakeholders and any other interested parties. Sprint retrospective is for the development team and the scrum master to reflect on their working practice, within the team.
    
6.  a) As a user I want to be able to log in, so that I can see information related to my account.  
    b) As a staff member, I want to be able to export orders to Excel, so that I can analyse the data.  
    c) As a user I want to be able to use dark mode, so that I can choose the viewing mode colour scheme that suits me.
    
7.  User story: As a customer, I want to see my order history, so that I can buy the same thing again.  
    Acceptance criteria 1: The user can see a list of their order history, ordered by date.  
    Acceptance criteria 2: The user can view the products in an order in their order history.  
    Acceptance criteria 3: The order history functionality works both on mobile and desktop.
    
8.  Definition of done for a team of four developers:
    
    - Automatic tests pass
    - Functionality has been tested on your local machine
    - Code has been reviewed by someone else
    - Comments from code review have been resolved
    - Manual tests pass
    - Code has been pushed to the main branch
9.  A daily scrum meeting should not take 45 minutes, it should be somewhere between 5-15 minutes. The purpose is not to report to the manager, but rather to check in as developers and resolve any possible blockers to keep the work going. Focus on that rather than daily reports to the manager.
    
10. a) Scrum: better suited for development and building new things  
    b) Kanban: better suited for IT support, since new tasks can arrive at any time  
    c) Kanban: better suited for software maintenance, since bugs can be reported at any time
    
11. The team should discuss the ratings. Each developer could give their reasons as to why they gave the rating. The developer who gave a 13 might have reasons that have been overlooked by the others that take more time. Discussing it will clarify if the extended time needed with a 13 is something that needs to be taken into account, or if a 2-3 is a more reasonable rating.
